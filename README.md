# CS-250-Portfolio
## CS 250 Portfolio Reflection

How do I find out what the user needs and put this into a program? How does user story creation help?

My understanding of user needs is to identify what the user really needs the program to do and then categorize those needs into smaller requirements. User stories aid in this process as they describe the feature from the user's perspective. This allows the development team to better understand the reason for the feature and not the technical side of it. User stories allow for better prioritising and easier iterations when feedback is provided.

How do I design programs? What are the Agile practices I wish to apply to my future development projects?

When developing programs, I like to divide the larger problem into smaller problems and work on these individually. I have learned from Agile that one doesn't need to have a fully completed program to receive valuable input. From now on I would like to try a process such as sprints and sprint planning, daily communication, and reviews and retrospectives. I think these methods would keep a project organised while allowing for changes in as new requirements and user needs change.

### What makes a good team member in software development?

In the field of software development, I think that a good team player means communicating, being reliable, and working cooperatively with people rather than seeing development as a solitary job. Team members should give honest updates, be willing to ask questions, and try to find solutions without throwing each other under the bus. I also think that it's important to be open to criticism because software development moves so quickly; the team has to adapt.
